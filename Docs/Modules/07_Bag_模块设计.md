# Bag 模块设计

## 模块定位

`Bag` 是统一的物品容器与变更入口，负责物品存取、奖励入库、消耗结算与来源追踪。它不定义“应该给多少奖励”“东西值多少钱”，那些规则归 `Economy`。

## 职责边界

负责：

- 物品存取
- 奖励入库
- 消耗结算
- 来源追踪

不负责：

- 价格表与货币规则
- 卡池概率
- 角色成长公式

## 首版功能要点

- 维护道具数量、堆叠、分类、排序
- 战斗、任务、抽卡等奖励统一入库
- 升级、突破、抽卡消耗统一扣减
- 记录每次增减的来源与去向

## 核心接口

- `AddItems(source, items)`
- `ConsumeItems(reason, items)`
- `HasEnough(items)`
- `QueryBag(filter)`

## 数据要求

- 物品主键统一
- 增减记录可追踪
- 重要变更写入日志与埋点

## 依赖关系

- 依赖：`Config`、`TelemetryLog`
- 被依赖：`Battle`、`Grow`、`Task`、`Gacha`、`Economy`

## 首版验收

- 所有奖励和消耗都经过统一入口
- 能精确知道某个物品的来源与去向
- 不允许业务模块私自修改库存数据

## 后续扩展

- 筛选、排序、批量操作
- 稀有道具锁定
- 与云存档冲突处理
