# 模块索引

> 本目录用于把重制工程拆成独立的模块子文档。目标不是把一个总方案越写越长，而是把每个模块的职责、输入输出、依赖关系、首版边界与后续扩展点单独固定下来，避免实现阶段再次出现“大总控”。

## 当前仓库中的真实痕迹

现有仓库并不是这些模块都已有实现。按当前代码与资源观察：

- `Battle`：已有较明确的新代码基础，集中在 `Assets/02_Scripts/03_Battle`
- `Login`、`MainCity`、`Gacha`：主要停留在旧实现，集中在 `Assets/02_Scripts/Before`
- `Formation`、`Grow`、`Bag`、`Task`、`Config`、`Save`、`Profile`、`Economy`、`HotUpdate`、`TelemetryLog`：当前以方案先行，后续重建

这意味着文档里的模块拆分是“目标结构”，不是“当前代码已经干净存在”的事实描述。实现时必须遵守：**先把模块边界写清，再落代码，不再让历史代码反向决定新架构。**

## 模块依赖总图

```text
Boot
  -> HotUpdate
  -> Config
  -> Save
  -> TelemetryLog
  -> Login

Login
  -> Profile
  -> Save
  -> MainCity

MainCity
  -> Profile
  -> Economy
  -> Task
  -> Bag
  -> Grow
  -> Formation
  -> Gacha
  -> Battle(入口)

Formation
  -> Profile
  -> Grow
  -> Bag
  -> Battle

Battle
  -> Config
  -> Formation(入场数据)
  -> Economy(奖励规则)
  -> Bag(奖励入库)
  -> Task(战斗目标推进)
  -> TelemetryLog

Grow
  -> Profile
  -> Config
  -> Bag
  -> Economy
  -> TelemetryLog

Gacha
  -> Config
  -> Economy
  -> Bag
  -> Profile
  -> TelemetryLog

Task
  -> Profile
  -> Config
  -> Economy
  -> Bag

Save
  -> Profile / Bag / Economy / 任务进度等状态的持久化
```

约束：

- `Battle` 不直接拥有养成与抽卡逻辑，只接收结果数据与入口数据
- `MainCity` 是导航与状态汇总中心，不是业务逻辑聚合中心
- `Bag` 负责统一入库与扣减，但不负责定义价格和奖励规则，规则归 `Economy`
- `Save` 只管持久化与迁移，不拥有业务状态解释权
