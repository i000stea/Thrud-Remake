# 外围系统设计（存档 / 配置 / 主城 / 养成 / 抽卡）

> 本文档定义核心战斗之外的所有系统：数据层（存档与配置表）、2D 主城功能页、三线养成、背包与货币、以及第二里程碑加入的抽卡。遵循决策 D08（2D 主城）、D09（三线养成）、D12（抽卡第二里程碑）。

## 数据层

### 存档模型

存档是单机版的"账号"，放 `PersistentDataPath/save/` 下，JSON 序列化 + 版本号迁移。

```
SaveData
 ├─ version          # 存档版本号（迁移依据）
 ├─ player           # 玩家信息：等级、昵称、货币
 ├─ heroes           # 持有角色列表：id, 等级, 星级, 碎片, 技能等级
 ├─ weapons          # 持有武器列表：id, 等级, 突破
 ├─ fafnir           # 简化符灵（预留复数，首版 1-2 格）
 ├─ bag              # 背包：物品 id → 数量
 ├─ progress         # 关卡进度：已通关、评价记录
 ├─ gachaRecords     # 抽卡记录（第二里程碑启用）
 └─ settings         # 画质/音量/键位等设置
```

- 写入时机：关键节点（战斗结算、养成升级、抽卡）+ 定期自动保存 + 退出保存
- 迁移机制：`ISaveMigration` 接口按 `version` 顺序执行，旧档可无损升级
- 预留：云存档接口 `ICloudSaveProvider`（本期空实现，配合网络抽象层）

### 配置表体系

所有内容数据（角色/武器/敌人/关卡/掉落/卡池/数值）走配置表，热更可更新（进 `config` 资源分组）。格式采用 JSON（版本控制友好、热更友好），配套编辑器工具可视化编辑与校验。

| 配置表 | 关键字段 | 说明 |
|--------|----------|------|
| HeroTable | id, 名称, 元素, 职业, 武器类型, 基础属性, 技能参数, 升星成长 | 角色模板 |
| WeaponTable | id, 类型, 子类, 基础属性, 弹匣/射速/换弹, 弹道参数 | 武器模板 |
| EnemyTable | id, 行为类型, 属性, 元素弱点, 掉落组 | 敌人模板 |
| LevelTable | id, 模式, 敌人生成序列, 目标条件, 评价权重 | 关卡模板 |
| DropTable | 关卡/敌人 → 掉落组 + 概率 | 掉落 |
| GachaTable | 卡池配置：内容, 概率, 保底（第二里程碑） | 抽卡 |

约束：配置表是**唯一**数值来源，代码中禁止魔法数字（伤害/CD/掉率一律查表）。编辑器工具负责表结构校验（字段类型、外键引用、概率和 = 1），错误在构建期阻断。

## 2D 主城功能页（D08）

主城以单场景 + UIKit 面板栈承载，功能宫格布局，保持原版"边缘弱化按钮、扩大中央空间"的界面理念：

| 入口 | 对应模块 | 状态 |
|------|----------|------|
| 出战 | Battle（编队 → 选关 → 进战斗） | M1 起可用 |
| 编队 | Grow（选择 ≤4 人上阵） | M1 起可用 |
| 角色 | Grow（角色列表 / 升级 / 升星） | M2 |
| 武器 | Grow（武器列表 / 强化 / 突破） | M2 |
| 符灵 | Grow（符灵装配） | M2 |
| 抽卡 | Gacha | M2 |
| 背包 | Bag | M2 |
| 设置 | 框架层 | M1 起可用 |

主城 3D 场景资产（`03_Module/MainCity`）保留但本期不加载，升级 3D 主城时直接把功能宫格挂到场景入口点即可。

## 三线养成（D09）

三条线的资源流设计成闭环：关卡产出 → 消耗于养成 → 提升战力 → 挑战更难关卡。

**角色**：等级（经验材料）+ 升星（碎片）+ 技能等级（绑定星级上限）

```
角色战力 = 基础属性 × 等级成长 × 星级倍率 × 技能等级系数
```

**武器**：等级（强化材料，可无损继承）+ 突破（材料消耗，突破提升等级上限与附加词条）

**符灵（简化）**：1-2 个装配格，提供数值增益（攻击%/生命%/元素强度）。首版不做符灵抽取，随关卡解锁或商店兑换。

材料与关卡挂钩示例（数值最终以配置表为准）：

| 材料 | 产出 | 消耗于 |
|------|------|--------|
| 经验药剂 | 清剿/防守关 | 角色、武器升级 |
| 强化合金 | 护送/防守关 | 武器强化 |
| 角色碎片 | 对应角色关/Boss 关低概率 | 升星 |
| 突破核心 | Boss 关 | 武器突破 |

## 货币

| 货币 | 获取 | 用途 | 说明 |
|------|------|------|------|
| 金币 | 关卡结算、出售 | 通用消耗（升级、商店） | 主要流通货币 |
| 能源（钻石位） | 关卡三星、活动、成就 | 抽卡、体力恢复（若有） | 稀有货币，第二里程碑起有消耗点 |
| 角色碎片 | 关卡、抽卡重复转化 | 升星 | 角色专属 |

首版不引入体力系统（避免运营向复杂度）；若后续需要限制刷取频率，再在配置层加体力，不影响数据结构。

## 背包

- 统一 `BagModel`：物品 id → 数量，物品定义表（id/类型/堆叠/用途）
- 变化通过 `BagItemChangedEvent` 广播（UI 自动刷新）
- 通用消耗接口：`BagSystem.Consume(id, count)`，所有消费路径（升级、抽卡、突破）统一走此接口，便于埋点与回滚
- 首版物品类型：材料、碎片、货币（货币单独字段，不进背包堆叠）

## 抽卡（M2，D12）

- 复用现有 `2GachaScene` 场景资产与抽卡逻辑（`Gacha_CoreOperation` / `Gacha_UIOperation` 作参考），按新架构重建
- 卡池：常驻池 + 限定池（配置表驱动）；保底与大保底（硬保底，数值可配）；单抽/十连
- 抽卡消耗：能源货币；重复角色转化为碎片（进升星循环）
- 结果流：调用 `GachaSystem.Draw(poolId, count)` → 概率表裁决 → 写背包/存档 → 广播 `GachaResultEvent` → 播演出（复用现有动画资产）
- 埋点：完整记录每抽（见性能与埋点文档），便于调概率与排查

## 任务与引导（轻量，M2 后按需）

- 主线任务：串联"通关 X 关 / 升级 Y 次"的成长引导，奖励货币与材料
- 每日任务：3-5 条轻量任务，给金币与能源（数值可配）
- 不做：赛季通行证、活动系统（超出重制范围）

## 埋点与日志的挂载点

本方案中各系统的关键动作（战斗进出、结算、升级、抽卡、货币变动）统一调用 `Telemetry` 模块的事件接口，事件定义集中维护，避免各模块自造日志格式。具体协议与落盘见 `05_性能优化与埋点日志.md`。
