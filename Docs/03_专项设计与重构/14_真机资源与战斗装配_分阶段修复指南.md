## 2. 决策：角色/武器资源走显式 AB（2026-09-10 用户定）

**做法（一步到位，只标一个资产）**：

1. 只把 `Assets/Data/BattleTeamCatalog.asset` 标记到新 assetBundleName **`battle_characters`**。
2. 角色/武器 SO、`rolePreafab` / `wepPrefab` / `bulletPrefab`、立绘与贴图**不要逐个标**——它们作为该资产的**依赖闭包自动入包**（Unity 既定规则）。
3. 运行时由 `BattleAssetService`（`03_Battle/Team/BattleAssetService.cs`）经 ResKit 显式加载该编目**并常驻持有**。
4. **不要**给 `Assets/Data/BattleLevels/BattleLevelCatalog.asset` 打标——它被场景 `battle_runtime.catalog` 引用，打标会让关卡数据在真机缺源（"被标 AB 的资产又被场景引用"这一类）。

**为什么必须常驻持有（不是可选项）**：AB 卸载会销毁其中已加载的对象，而战斗装配 / 换人 / 切武器会在运行时反复按 itemID 解析同一批 SO 与 prefab。只要还有静态引用，就不能让引用计数归零（09 关键坑 26 的教训）。因此 `BattleAssetService` 用一个**永不回收的 `ResLoader`** 持有该 bundle，只在显式 `Release()`（未来热更/主动卸载入口）时释放。

**解析顺序（已在代码中落地，AB 优先）**：

| 位置 | 顺序 |
|------|------|
| `BattleSceneRuntimeHost.ResolveTeamCatalog()` | ① `BattleAssetService.ResolveCatalog()`（AB） → ② 场景 `teamCatalog` 字段（兜底） → ③ 编辑器 `AssetDatabase` 直读（仅编辑器） |
| `Main_FormationPanel.ResolveCatalog()` | ① 注入的 `Main_FormationPanelData.Catalog` → ② `BattleAssetService.ResolveCatalog()`（AB） → ③ prefab 序列化 `catalog`（兜底） |

**已知副作用与观察项**：

- 正面：`main_formationpanel_prefab` 的体积会回落（编目与其闭包从"嵌在面板包里"变成"面板包对它的一条 bundle 依赖"）。
- 重复（可接受，不会缺源）：`Role-Geweidelin.prefab` 被 `2MainScene.unity` 引用、4 个玩家子弹 prefab 被 rig prefab（场景实例）引用 → 它们在 Player 构建里各有一份，AB 里还会再嵌一份；P3 再收敛。
- **shader 风险**：AB 内容用到的 shader 若在构建数据里没有引用，同样会被剥离 → 表现为角色材质变粉/丢失。真机若出现，把对应 shader 加入 `Project Settings → Graphics → Always Included Shaders`（link.xml 管不了 shader）。**这条必须写进 P0 的真机观察项。**

### P2 · AB 加载异步化（1 天，用户已选「全量异步」）

- 目标：消除"读 AB + 载资源"的同步主线程卡顿。
- 改动范围：
  1. `UiPanelFlow.TryOpenAsync<T>(...)`（IEnumerator）：先 `SanitizeRegistry()` → `yield return UIKit.OpenPanelAsync<T>(level, uiData, bundle, prefab)` → 用 `GetPanel<T>()` 判成败 → **必须加超时兜底**（`ResKitPanelLoader.LoadPanelPrefabAsync` 只在成功时回调，失败无回调，无兜底会永久等待）；
  2. 调用点全量改造：触摸层（宿主已是协程）→ 主菜单 / 选关 / 编队（点击回调协程化）→ 战斗内结算 / 暂停（`BattleUiSystem` 是 `AbstractSystem`，需 `BattleSceneRuntimeHost` 提供协程入口）；
  3. 面板关闭后的 `AssetBundle.Unload(true)` 仍是主线程成本 → 本阶段**只测量、不改释放策略**。
- **边界（避免期望错位）**：异步只覆盖 `AssetBundle.LoadFromFileAsync` 与 `LoadAssetAsync`；`UIKitConfig.LoadPanelAsync` 内部的 `Object.Instantiate(prefab)` 与首次字体图集上传仍在主线程 → 卡顿**明显减轻但不会归零**；要归零必须配合 P3 的包体削减。
- **退出条件**，真机：每个面板首开、复开各打点计时（`[Perf] panel open ms=…`），对比 P1 基线有明确下降；无白屏、无交互失效、无面板残留。
- 风险：QFramework 的 `OpenUIAsync` 路径本工程从未实际使用 → 必须先在编辑器 SimulationMode 下把所有面板压一遍再上真机。
