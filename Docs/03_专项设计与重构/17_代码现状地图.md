### 3.2 边界判定口径（后续新增类型时照此判断）

> 一个类型该不该进契约层，只问一句：**Menu 是否需要看见它？**
> - 需要 → 进契约层（连它的公开字段/特性所暴露的类型一起进，否则成环）
> - 不需要 → 留在 `TeaGame.Battle`
>
> **反面例子（本次未下沉，刻意留在 Battle）**：`BattleTeamRuntimeBuilder`（Menu 不装配角色实体）、`BattleRoleRuntimeData`/`BattleRuntimeBridge`（战斗内部运行时数据）、`BattleLevelFlow`/`BattleStageDirector`（战斗流程与刷怪）、`BattleUiSystem` 与战斗面板（`Battle_LevelResultPanel` 等，Menu 从不开它们）。

> ⚠️ **纪律**：契约层不是"Battle 的 public API 汇总"。下沉一个类型会连带它的整个公开面，容易滚成新的 God assembly。新增时按 §3.2 判定，并回填本表。
