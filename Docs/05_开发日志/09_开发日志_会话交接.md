12. **移动/瞄准"视角正前"模型（2026-09-02 定稿，含用户多轮手感反馈）**
    - 灰盒是空域自由移动+自由射击。**移动**：`BattlePlayerConfig.MoveForwardFollowView`（默认 `true`）——WASD 前进以相机正前方（含俯仰）为基准；`false` 退回水平 yaw。侧向与 Q/E 升降始终按水平 yaw 基准。**模型朝向**：`UpdateShowView` 使展示模型跟随视角（含俯仰，`ClampLookRotation` 无 roll、俯仰限幅 ±80°）。
    - **瞄准（锁敌优先）**：锁定时 legacy 武器自身 Update 平滑吸附锁定目标（Bridge 只提供真实 `LockPoint`），新版组件走 `RefreshAim` 平滑。**未锁定时武器姿态回正**：legacy `Weapon_ObjectComponent` 把 localRotation 收敛到 `0,0,0`（新版组件 `RefreshAim(null)` 同理），不再让武器指向远处虚拟点（曾试 10m/999m 指向点方案观感不佳，已废弃）。

    - **做法**（脚本已落盘可复用：`Build\_check\CheckBattle.ps1`；`Build/` 已 gitignore，不进库）：用
      `Editor\Data\MonoBleedingEdge\lib\mono\msbuild\Current\bin\Roslyn\csc.exe`（经同目录 `MonoBleedingEdge\bin\mono.exe` 运行）
      编译**目标程序集的全部源码**；引用 = `Library\ScriptAssemblies\*.dll`（**Unity 上一次导入产出的引用程序集**，排除目标程序集自身与 `Assembly-CSharp*`）
      + `Editor\Data\Managed\UnityEngine\*.dll`（编辑器目标另加 `UnityEditor.dll`）+ `NetStandard\ref\2.1.0\netstandard.dll`
      + `NetStandard\compat\2.1.0\shims\netfx\*.dll` + `Assets\Plugins\Demigiant\DOTween\DOTween.dll`。
      调用：`powershell -File Build\_check\CheckBattle.ps1`（编辑器目标）／`-Player`（player 目标 = **热更 DLL 的编译面**）。
    - **三个坑（都踩过）**：① 把 `-r:"a;b;c"` 直接拼进命令行会被 mono 在含空格路径上拆坏（报 `CS2005 Missing file specification for '-r:' option`）→ **必须写响应文件**（`@file.rsp`，一行一个参数）；② 缺 `netstandard 2.1` → `CS0012`，缺 `shims\netfx` → `CS0518`；③ **漏 DOTween** → 报 `CS0103 DOTween 不存在` / `CS0012 TweenerCore`（它不是 Unity 包程序集，不在 `Library/ScriptAssemblies`）。
    - **价值与局限**：这是**真实 csc + 真实引用**，能查出跨文件签名不一致、成员不存在、`#if` 分支写错（`-Player` 配置专测 `#else` 分支，本轮就是靠它验证正式构建的失败回落分支）；但**不等于 Unity 导入编译**（不跑 asmdef 解析、不生成 `.meta`、不报导入期错误），更**不替代 Play**。结论口径照抄："离线整程序集编译通过（编辑器/player 各 0 error CS），Unity 导入编译与 Play 未验"。

35. **把"早退"重构成"返回布尔 + `out` 参数"时，必须定义失败时 `out` 的契约（2026-09-19 自查发现，已修）**
    - 实例：宿主 `TryResolveLevel(out level)` 原本用 `if (!...) { return; }` 早退，语义天然安全；搬进 `BattleSetupSystem` 改成 `bool TryResolveLevel(..., out BattleLevelData selected)` 后，宿主**忽略了返回值**，而 False 分支上 `selected` 仍可能是"**属于别的美术场景**的会话关卡"（`catalog` 为空 + 会话关卡与本场景不符的那条路径）→ 会把错的关卡注入 `BattleStageDirector`。
    - 规律：**`out` 参数在 `false` 时不保证为空**，除非方法自己写明并置空。凡做这类"早退 → bool/out"的搬运，① 方法失败即把 `out` 置空/null 并注释；② 调用方必须消费返回值，不许"只取 out、不看 bool"。
    - 同类隐患点（下次做类似搬运时逐条看）：`TryResolveLevel`、`BattleObjectPool.TryXXX`、`ResKitBootstrap.TryResolve`、`BattleAssetService` 的解析入口。
