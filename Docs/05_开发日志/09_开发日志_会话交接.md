## 3. 关键决策与坑（务必先读，避免重蹈）

1. **旧版 PlayerControl 组件已从 prefab 移除（根治）**
   `PlayerControl.prefab` 根节点曾同时挂 `TeaFramework.PlayerControl`（旧）与 `TeaGame.PlayerControl`（新）。
   旧版依赖 `StoreBattleRoleData.I` 填充数据，灰盒没有该对象 → 每帧 `IndexOutOfRangeException`；
   且旧版 `P_Aim` 与新版 `BattleAimSystem` 争抢同一准星 `Cross_LockEnemy` → 锁敌吸不住。
   **现状：旧版组件已从 prefab 删除**，灰盒/Test0/Test1 均只走新版系统。
   若未来再引入 prefab，勿把旧组件加回来。

2. **血条刷新方案**
   `Health_Main` 是 Sliced 类型、左锚点固定宽度(554)的 Image。新版由 `BattleViewSystem` 订阅
   `BattlePlayerDamagedEvent`/`BattlePlayerDiedEvent` 事件驱动，按比例改 `sizeDelta.x`（沿用旧版 P_VisualEffect 方案）。
   `Health_Value` 同步显示 `当前/最大`。不要改成每帧刷新（违反无每帧 GC 纪律）。

3. **死亡接管必须同步 `Controller.ControlTakeOff = true`**
   `PlayerControl.Update` 每帧用自身字段覆盖 `State.ControlTakenOver`。
   `BattleHealthSystem` 归零时若不写 `State.Controller.ControlTakeOff`，死亡接管会被立即写回 false，角色死亡后仍可操作。

4. **冒烟测试 asmdef 方案已废弃**
   `Assets/Test/BattleGrayboxSmoke/` 曾放 PlayMode 测试，asmdef 首轮导入时序导致 NUnit 引用丢失、编辑器控制台报错，已删除。
   **验证一律走手动 Play Mode**（卡片内"验证方式"即为此设计）。

5. **Unity 编辑器占用工程时无法批量模式**
   用户编辑器开着工程（`Temp/UnityLockfile`）时不能跑 `-batchmode`。场景生成/验证都在编辑器内完成。
   Unity 路径：`D:\Program Files\Unity\Editor\2022.3.60f1c1\Editor\Unity.exe`（版本 2022.3.60f1c1）。
   本机 dotnet 无 SDK，无法用 Roslyn 独立编译校验 → 以 Unity 编辑器编译结果为准。

6. **敌人开火链路（灰盒可验证受击）**
   `BattleEnemyEntity.TickShoot` 每 3-5s 一发 `EnemyBullet.prefab`（speed 8，弹道飞行约 1.6s 命中）。
   `BattleEnemyBullet.OnTriggerEnter` → `BattlePlayerDamagedEvent` → `BattleHealthSystem` 扣血（4-7 点）。

8. **对象池纪律（T1.3 前现状）**
   目前射击/敌人子弹仍是 `Instantiate`/`Destroy`（`BattleWeaponModeBase.FireSingleShot`、`BattleEnemyEntity.TickShoot`）。
   T1.3 统一改 `BattleObjectPool`（子弹每武器 64-128、敌人子弹 128、命中/超时回收、场景加载预热）。

9. **事件驱动纪律**：系统间通信用 QFramework `SendEvent`/`RegisterEvent`，禁止模块间直接引用。

10. **MonoBehaviour 必须独立文件才能被 prefab YAML 序列化引用（2026-09-02 实测踩坑）**
    手写 prefab YAML 的 `m_Script` 引用 `{fileID:11500000, guid:…}` 中，`11500000` 只在"该脚本文件里唯一 MonoBehaviour 类"时精确对应类。
    `BattleBullet` 原先与 `BattleWeaponObjectComponent` 等同在 `BattleWeaponRuntime.cs`（多类文件），按 `11500000 + 文件 guid` 引用后组件绑定失败（子弹上显示为 "BattleWeaponRuntime"）。
    **规则：需要在 prefab/场景里挂载的 MonoBehaviour 一律单独放一个 .cs 文件**；代码内类型引用（GetComponent 等）不受此限制。`BattleBullet` 已拆为 `Weapon/BattleBullet.cs`（新 guid）。

11. **目录移动纪律（2026-09-02 模块化整理）**：移动 Unity 资产时必须 `.cs` 与 `.cs.meta` **成对**移动，guid 保持不变，否则 Unity 会生成新 guid 导致所有 prefab/场景序列化引用断裂。

12. **移动/瞄准"视角正前"模型（2026-09-02 定稿，含用户多轮手感反馈）**
    - 灰盒是空域自由移动+自由射击。**移动**：`BattlePlayerConfig.MoveForwardFollowView`（默认 `true`）——WASD 前进以相机正前方（含俯仰）为基准；`false` 退回水平 yaw。侧向与 Q/E 升降始终按水平 yaw 基准。**模型朝向**：`UpdateShowView` 使展示模型跟随视角（含俯仰，`ClampLookRotation` 无 roll、俯仰限幅 ±80°）。
    - **瞄准（锁敌优先）**：锁定时 legacy 武器自身 Update 平滑吸附锁定目标（Bridge 只提供真实 `LockPoint`），新版组件走 `RefreshAim` 平滑。**未锁定时武器姿态回正**：legacy `Weapon_ObjectComponent` 把 localRotation 收敛到 `0,0,0`（新版组件 `RefreshAim(null)` 同理），不再让武器指向远处虚拟点（曾试 10m/999m 指向点方案观感不佳，已废弃）。
    - **未锁定弹道**：`BattleWeaponSystem` 每帧写 `BattleWeaponModeBase.FreeAimRotation = 相机旋转`（锁定时置空）；`FireSingleShot` 与狙击射线均以该基准旋转/方向发射 → **子弹打向准星/视角正前（含俯仰），武器模型却保持 0,0,0**。
    - `WepLookatTarget` 仅保留为调试表现点（未锁定放相机前 10m），不参与武器朝向与弹道。

13. **接口引用不能判 Unity 已销毁对象（2026-09-02 修复 MissingReferenceException）**
    `BattleStateModel.LockEnemy` 类型是接口 `IBattleEnemyTarget`；接口判空不触发 `UnityEngine.Object` 的 `==` 重载，敌人 `Destroy` 后 `!= null` 仍为 true → 访问 `LockPoint` 抛 `MissingReferenceException`（敌人死亡时报错）。
    处理：新增扩展 `BattleCombatUtility.IsAlive(IBattleEnemyTarget)`（Object 实现按 `UnityEngine.Object` 判空；纯托管实现如 `LegacyBattleEnemyTarget` 非空即存活）；所有 `State.LockEnemy` 读取点（AimSystem 每帧清理/ViewSystem/SyncRuntimeBridge/WeaponSystem 自由瞄准判断）统一改用 `IsAlive()`。**教训：以接口持有的 UnityEngine.Object 引用，判空必须显式转 Object 或走 IsAlive 类封装。**

14. **T1.4 命中反馈三处修正（2026-09-02，用户实测反馈）**
    - `BattlePoolAutoReturn` 从 `BattleObjectPool.cs` 拆为**独立文件** `Pool/BattlePoolAutoReturn.cs`（同第 10 条纪律：MonoBehaviour 组件一律独立成文件）。
    - 命中特效出现在敌人**后侧/相机看不到**：根因是 trigger 回调时子弹已高速穿过碰撞体，直接取当前位置会落在背面。修复（用户建议的"倒退+射线"方案）：`BattleBullet.ResolveEntrySurfacePoint` 沿子弹飞行方向倒退 2m 到体前，再对该碰撞体 `Raycast` 取首个表面交点作为真实命中点，并向子弹来向外推 0.1m；掠射 miss 时回退 `ClosestPoint(倒退点)`。
    - `BattleHitSpark.prefab` 网格 fileID `10208`(胶囊) → `10207`(球体)。

18. **asmdef 边界：Editor 代码必须独立 Editor-only 程序集（2026-09-08，切 Android 才暴露）**

19. **UIKit 的 UIRoot 归属与跨场景面板丢失（2026-09-08，T1 触屏层踩坑）**
    - `UIRoot.Instance` 若在场景里找到已存在的 UIRoot 就**直接复用、不做 DontDestroyOnLoad**；本项目 `2MainScene` 与 `BattleGraybox` **各自带 UIRoot 场景实例**。
    - 现象：从主菜单进战斗时若立刻 `OpenPanel`，面板挂到**2MainScene 的 UIRoot** 下 → SceneFlow 随后卸载 2MainScene → 面板随旧场景销毁 → 战斗中触摸 UI 消失（直接 Play BattleGraybox 则正常）。
    - 修复：`battle_runtime.Start` 用协程**等 `UIRoot.Instance` 归属稳定**（属于本场景 / `DontDestroyOnLoad` / 不存在）再打开面板；`TryOpenForBattle` 顺带清理跨场景残留面板表项。

20. **SceneFlow 时序纪律（2026-09-08）**
    - **不要在 `LoadSceneAsync` 未完成（`allowSceneActivation=false`）期间卸载其它场景**——会中断本次加载；"先卸载旧的再激活新的"在 additive 模式下不可行。
    - 正确顺序：预加载 → 激活新场景 → `SetActiveScene` → 卸载旧玩法场景（逐个 `yield return` 等完成）→ 渐隐遮罩。
    - `LoadRoutine` 必须 `try/finally` 复位 `mSwitching`：协程一旦异常而不复位，之后所有 `RequestLoad` 都被"正在切换中"永久拦截（场景再也切不动）。
    - `FadeCanvasGroup` 对已销毁的 CanvasGroup 必须先判空返回（旧写法 `canvasGroup == null` 时仍写 `alpha` → NRE 中断切换协程）。

21. **TMP 下划线警告（2026-09-08）**
    - TMP 下划线表现使用特殊字符 `0x5F`（`_`）；字体资产缺该字符时，编辑器内每个 `TMP_Text.OnValidate` 都刷一条
      「The character used for Underline is not available in font asset [...]」。
    - 修复：菜单 `Thrud/Tools/TMP/Fix Missing Underline Character (0x5F)`（Dynamic 字体 `TryAddCharacters("_")` 并保存；Static 需重建图集）。
    - 另：触摸面板按钮标签**不要用 uGUI 内置字体**（`LegacyRuntime.ttf` 不含中文）——统一用项目中文 TMP 字体 `zh_SansSerif-1 UILanTing_Small_GBK SDF`。

22. **UIKit.OpenPanel 必须显式传 prefabName（2026-09-08，真机 AB 加载失败）**
    - `ResKitPanelLoaderPool.ResKitPanelLoader.LoadPanelPrefab`：未传 `prefabName` 时走
      `LoadSync(PanelType.Name)`（**无 bundle、资源名被小写规范化**）→ 编辑器模拟可能侥幸通过，
      **真机/AB 模式必报** `Failed to Create Res. Not Find By ResSearchKeys: AssetName:main_menupanel…`。
    - 修复：所有 `UIKit.OpenPanel<T>(level, uiData, bundleName, prefabName)` 补传 `prefabName`
      （= prefab 文件名，走带 bundle 的分支）。已修 `Main_MenuPanel`/`LevelSelectPanel`/`Main_FormationPanel` 三处；
      结算/暂停/触摸层/Bootstrap 本就传了，不受影响。

23. **ResKit 在打包后必须显式初始化（2026-09-08，真机面板全部加载失败）**
    - `ResKit.CheckAutoInit` 带 `#if UNITY_EDITOR`：**仅编辑器 + SimulationMode** 下自动 `Init()`；
      打包后无人调用 → AB 清单（asset_bundle_config.bin）未加载 → UIKit 面板经 ResKit 加载

    - 修复：`AppBootstrapper.Start` 开头 `yield return QFramework.ResKit.InitAsync();`
      （真机从 StreamingAssets 异步读清单；编辑器 Simulation 已 Init 则立即完成，幂等）。
    - 编辑器联调建议保持 ResKit 窗口的 SimulationMode 勾选（EditorPrefs `SimulateAssetBundles` 默认 true）。

24. **战斗装配职责收口（2026-09-08 架构调整，用户 review 提出）**
